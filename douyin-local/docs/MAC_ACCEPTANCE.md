# Mac 实机验收（当前未执行）

当前结论：`not tested on Mac`。以下每项都需要在用户 Mac 运行，不传 Cookie 到云端。

1. 记录 macOS 版本、arm64/x86_64；首次安装是否无需 Xcode 完成，安装检查是否报错。
2. 双击启动，默认浏览器是否打开 127.0.0.1；另一个可见 Chromium 是否可正常登录。
3. 输入 `https://v.douyin.com/xsZCGxFbWTQ/` 或 `https://www.douyin.com/video/7673835272434296714`（示例可能失效，必要时换成你有权下载的公开单集）。记录是否解析到正式 mix_id、名称、平台总数、查询集数。不得仅凭标题相似判断合集。
4. 与抖音正常页面核对集序、总数。若同源 detail/mix 接口因缺少平台签名返回拒绝，工具必须报告失败；不要添加伪造指纹、签名生成器或绕过方式。该结果意味着当前查询适配未通过真实验收，需依据正常页面允许的数据方式修正。
5. 确认后下载，记录总集数、实际 MP4 数、成功/失败/缺集，逐集与平台原文比较，抽查首尾视频播放。没有独立 title 时 null 是正常结果，不能用文案冒充原标题字段。
6. 中断并重启，从历史恢复；已校验文件不重复下载。移走一集或损坏副本后重试，应只重下受影响集。不要为了测试主动触发平台限流。
7. 自然遇到 403/验证码时确认后续集不再下载；在正常网站完成认证后点重试。鉴权失败不能显示“下载成功”。
8. 无正式合集的视频应明确拒绝，不下载整用户作品；未知总数不显示齐全。
9. 关闭窗口后服务停止；Finder 打开目录；自定义输出路径可用。

请只反馈非敏感的版本信息、状态和计数。不要分享 Cookie、浏览器资料目录、签名媒体地址或含账号信息的完整日志。
